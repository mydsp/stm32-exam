# 02 · VOFA+ 上位机调试舵机 · 开发文档

对应《G308 电控组 2026 年夏季考核题》软件部分第二题。
硬件：STM32F401RET6 + MG996R 舵机 ×2 + USB 转串口。
仓库：[github.com/mydsp/stm32-exam](https://github.com/mydsp/stm32-exam)

## 1. 项目概述

上位机通过自定义协议下发两路舵机的目标角度，STM32 解析后驱动舵机，并以 20Hz 回传
"当前角度 + PWM 占空比"共四通道数据，在 VOFA+ 中以 JustFloat 曲线实时可视化。

| 题面要求 | 实现 |
| --- | --- |
| （1）从 VOFA+ 发送目标角度，舵机响应 | 12 字节下发帧，滑窗收帧后限幅并写 CCR |
| （2）实时返回当前角度与 PWM 占空比 | 20Hz 回传 4 通道 JustFloat |
| （3）按 JustFloat 规定格式可视化 | 回传帧尾固定 `00 00 80 7F`，数据引擎选 JustFloat |
| 提交：项目文件 / 开发文档 / 实操视频 | 本仓库 / 本文 / `docs/video/soft2-demo.mp4` |

## 2. 硬件与接线

| 引脚 | 连接 | 说明 |
| --- | --- | --- |
| PA9（USART1_TX） | USB 转串口 RX | 115200-8-N-1 |
| PA10（USART1_RX） | USB 转串口 TX | 双向通信 |
| PA6（TIM3_CH1） | 舵机 1 信号线 | 50Hz |
| PA7（TIM3_CH2） | 舵机 2 信号线 | 50Hz |
| 外接 5V（≥3A） | 舵机电源 | 独立供电，与 MCU 共地 |

MG996R 堵转电流在 2.5A 量级，不能从开发板 USB 口取电，否则电压被拉垮会导致 MCU 复位。

## 3. 通信协议

收发两个方向均以 JustFloat 帧尾 `00 00 80 7F` 作为对齐标记。

**下发（上位机 → MCU，12 字节）**：字节 0~3 为 pan 目标角（float32 小端，0~180），
4~7 为 tilt 目标角，8~11 为帧尾。
示例 pan=30°、tilt=90° → `00 00 F0 41 00 00 B4 42 00 00 80 7F`。

**回传（MCU → 上位机，20 字节，20Hz）**：

| 通道 | 含义 | 单位 |
| --- | --- | --- |
| ch0 / ch2 | pan / tilt 当前角度 | 度 |
| ch1 / ch3 | pan / tilt PWM 占空比 | % |

换算关系：`脉宽 = 500 + 角度 × 2000 / 180`（µs），`占空比 = 脉宽 × 100 / 20000`。
90° 对应 1500µs、7.5%；30° 对应 833µs、4.165%。

## 4. 软件设计

裸机实现，单个 `while(1)` 内完成收发，不使用中断与 DMA：

```
main()
 ├─ SystemClock_Config()    HSI → PLL → 84MHz
 ├─ UART1_Init()            USART1 115200-8-N-1
 ├─ PWM_Init()              TIM3 CH1/CH2，50Hz，上电 1500µs 中位
 └─ while(1)
      ├─ RX_Pump()          12 字节滑窗收帧 → 解析 → 限幅 → 写 CCR
      └─ 每 50ms            Send_JustFloat() 回传 4 通道
```

**滑窗收帧**：JustFloat 只有帧尾没有帧头，串口中途接入或丢字节都会造成字节流错位。
因此维护一个 12 字节窗口：未满时顺序填入，填满后左移一字节并补入新字节；
仅当第 8~11 字节恰为 `00 00 80 7F` 时认定整帧有效，取前 8 字节解析并清空窗口重新对齐。
由于 0~180 范围的 float 编码不可能拼出该帧尾，滑窗不会在数据段误触发。
这是"收敛式对齐"：接入后的头几十毫秒数据不可信，之后即为稳定对齐。

**占空比回传**：占空比由当前 TIM3 CCR 换算而来，是硬件真实输出的反映；
角度回传的是最近一次下发的指令角。MG996R 为内置闭环的模拟舵机，没有对外的位置接口，
在未加装外部编码器的条件下，回传"实测角度"不具备实现基础，因此通道语义明确标注为指令角。

## 5. VOFA+ 使用与验收

1. 新建串口连接，波特率 115200，数据引擎选 **JustFloat**，波形区出现 4 条平线即为在收。
2. 命令区新建命令，类型选 **Hex**，填入完整 12 字节下发帧并发送。
   注意 JustFloat 是接收侧的数据引擎选项，命令区只有 `Hex` 与 `ABC` 两种格式。
3. 发送 pan=30°：舵机由 90° 转至 30°，ch0 阶跃到 30、ch1 落至约 4.165%。
4. 发送 pan=60°：`00 00 70 42 00 00 B4 42 00 00 80 7F`，ch0 约 60、ch1 约 5.83%。

实测读数：ch0=30.000 / ch1=4.165 / ch2=90.000 / ch3=7.500，与理论值一致。

## 6. 构建与烧录

```powershell
cmake --preset Debug ; cmake --build --preset Debug
pyocd flash -t stm32f401retx build\Debug\stm32-exam.bin
```

## 7. 已知限制

- 回传角度为指令角，非传感器实测（见 §4）。
- 软件限幅 0~180°；如需避开机械行程端点，在限幅参数中收窄使用范围即可。
- 回传频率 20Hz，满足趋势观测；如需观察毫秒级动态需提高回传率。

## 8. 调试记录

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 命令区填 `30 90` 舵机不动 | 字节数不足、帧尾不匹配，滑窗无法对齐 | 命令区选 Hex 并填完整 12 字节；JustFloat 仅用于接收数据引擎 |
| 回传的是脉宽微秒数 | 与题面要求的占空比量纲不符 | 新增 `pulse_to_duty_pct()`，回传通道改为占空比，文档同步更新 |
| 舵机转动时板子复位、串口乱码 | 舵机堵转电流拉垮 USB 5V | 舵机独立 5V≥3A 供电，与 MCU 只共地 |
| 波形偶发乱跳 | 字节流从中途接入导致错位 | 滑窗按帧尾收敛对齐；接入后的初始数据不采信 |
